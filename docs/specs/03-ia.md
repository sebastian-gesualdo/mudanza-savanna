# 03 · IA con prioridad a Jev

## Decisión

El usuario quiere utilizar Jev todo lo posible por su bajo costo. La arquitectura prioriza:

1. Código y datos exactos para acciones explícitas, cálculos y lecturas por identificador.
2. Jev para decisiones semánticas entre opciones conocidas, relevancia, clasificación y detección de ambigüedad.
3. Modelo generativo de mayor capacidad únicamente cuando hace falta producir o extraer texto libre que las rutas anteriores no resuelven. El 14/10/2026 el usuario pidió priorizar calidad y retirar Gemini 2.5 y GPT 5.4.

“Priorizar Jev” no significa llamar a un modelo para sumar cantidades o pulsar Cerrar. Tampoco significa atribuirle capacidades de transcripción, generación libre o ejecución de SQL que no provee.

## Capacidades verificadas y límite técnico

Fuentes oficiales consultadas el 11/10/2026:

- [SDK oficial de TypeSafe](https://github.com/typesafe-ai/typesafe-sdk-js) y [tipos de respuestas](https://github.com/typesafe-ai/typesafe-sdk-js/blob/main/src/types.ts).
- [Decisiones en Vercel AI SDK](https://github.com/vercel/ai/blob/main/content/docs/03-ai-sdk-core/32-decisions.mdx).

Jev recibe texto/JSON y preguntas tipadas. Puede elegir una opción (`Choice`), puntuar según una rúbrica (`Score`) y estimar una respuesta booleana (`Noul` en TypeSafe; `boolean` en el adaptador del SDK). No genera arbitrariamente el nombre de un objeto nuevo como respuesta a una opción múltiple.

La documentación consultada permite `typesafe-ai/jev` mediante Gateway y `experimental_decide` en AI SDK. La interfaz es experimental y puede cambiar incluso en versiones patch. Encapsularla en un adaptador, fijar versiones y verificar el paquete publicado antes de depender de esos símbolos. No copiar ejemplos de APIs anteriores como `experimental_evaluate` sin comprobar compatibilidad.

Las preguntas de una evaluación son independientes y comparten estado. No asumir que la respuesta a una pregunta modifica el contexto de la siguiente. TypeSafe acepta texto/JSON; la capacidad multimodal de otros adaptadores no habilita imágenes o audio en Jev.

## Integración

- Backend en Vercel → AI SDK → AI Gateway → Jev o modelo generativo elegido.
- Credencial de Gateway u OIDC admitido por Vercel, siempre en servidor. No requerir `OPENAI_API_KEY` ni conexión directa a OpenAI.
- `DECISION_MODEL` por defecto: `typesafe-ai/jev`, sujeto a verificación de acceso en T00.
- `GENERATION_MODEL`: identificador de Gateway elegido en T00 comparando costo y exactitud con los ejemplos del proyecto. Priorizar calidad conforme al pedido del usuario, con tarifas verificadas y el mismo límite de gasto.
- Si la versión disponible del SDK no soporta esta ruta, resolver con una integración oficial compatible. No inventar endpoints ni incorporar claves de otro proveedor silenciosamente. Documentar cualquier dependencia adicional.
- Dos adaptadores internos: `DecisionService` para preguntas tipadas y `ExtractionService` para propuestas estructuradas de texto libre. El resto de la aplicación no depende de nombres de métodos experimentales.

## Pipeline de un mensaje

1. Validar sesión de Supabase Auth, membresía activa, límites y UUID del mensaje; recuperar una respuesta ya procesada si existe y pertenece al participante/conversación autorizados. Google Login por sí solo no habilita gasto de IA.
2. Capturar conversación, unidad activa, idioma y contexto enviado. Resolver comandos estructurados del cliente sin IA.
3. Aplicar coincidencias inequívocas: código completo, alias exacto de ambiente, consulta de ficha, modo explícito de agregar contenido.
4. Si hace falta interpretación, evaluar con Jev una intención y las elecciones pertinentes sobre candidatos reales. Incluir alternativas `ambiguous`, `multiple_actions` y `unknown` cuando corresponda.
5. Validar coherencia entre respuestas independientes, campos obligatorios y referencias. Una probabilidad alta no habilita campos inexistentes ni omite una validación.
6. Construir una lectura o un comando determinista si todos los argumentos están sustentados. Para una descripción nueva, conservar el texto literal cuando el modo permita hacerlo.
7. Si falta un dato, ofrecer una aclaración breve. Si el pedido requiere extracción libre/composición y no alcanza una aclaración simple, utilizar como máximo una llamada generativa inicial para proponer el plan completo.
8. Validar el plan; aplicar la política de confirmaciones y ejecutar a través del servicio transaccional.
9. Renderizar plantilla y tarjetas con datos confirmados. No pagar una segunda llamada generativa solo para escribir “Listo, guardado”.

En caso de fallo transitorio se permiten reintentos acotados y presupuestados. No crear un bucle de agentes ni reintentos ilimitados para producir un JSON válido. Si la extracción sigue fallando, mantener el texto y ofrecer los controles manuales.

## Matriz de decisiones

| Caso | Ruta preferida | Salida |
| --- | --- | --- |
| Tocar Crear/Cerrar/Llegó | Código | Comando tipado. |
| “Qué hay en C-012” | Código y lectura directa | Ficha/plantilla con evidencia. |
| “Cuántas cajas de Kitchen faltan llegar” | Filtros explícitos + SQL; Jev solo si el filtro es ambiguo | Conteo exacto y alcance. |
| Elegir ambiente entre los 17 | Alias exacto; Jev si la expresión lo requiere | `room_id` válido o aclaración. |
| Elegir entre cajas/objetos existentes | Jev sobre candidatos | UUID o ambigüedad; nunca inventar un código. |
| Dictar contenido en modo Agregar | Guardar texto literal | Nueva entrada sin generación. |
| Clasificar intención de un mensaje libre | Jev | Intención del catálogo o múltiples/desconocida. |
| Buscar “hervidor” donde figura “pava eléctrica” | Recuperación de candidatos + Jev | Resultados ordenados y texto que respalda cada uno. |
| Descripción libre con varias operaciones y cantidades | Extracción generativa si las rutas anteriores no alcanzan | Propuesta validada, sin ejecución dentro del modelo. |
| Respuesta de una operación exitosa | Plantilla | Recibo de la transacción. |
| Comparar muebles históricos dudosos | Jev, opcional | Sugerencias para revisión, nunca equivalencia confirmada automáticamente. |

## Contenido y extracción

Jev puede seleccionar un fragmento si el programa ya generó candidatos finitos, pero no exigir una llamada por palabra para simular extracción libre. Para “puse varias cosas del mueble azul” basta conservar esa descripción.

No separar automáticamente cualquier coma: los registros contienen aclaraciones, cantidades y nombres compuestos. La extracción generativa devuelve un esquema validado con referencias a texto de origen, no SQL ni herramientas arbitrarias. Rechazar operaciones que no estén sustentadas en el pedido.

Pedidos con varias acciones sobre una misma unidad pueden ejecutarse como un único compuesto si son inequívocos. Operaciones sobre varias unidades presentan vista previa y confirmación.

## Búsqueda semántica

1. Buscar coincidencia exacta de código/nombre y contenido activo con normalización, búsqueda textual y trigramas de PostgreSQL. Conservar términos originales para el usuario.
2. Para consultas semánticas, pasar a Jev consulta, estado actual y un conjunto pequeño de candidatos con IDs. Incluir contexto suficiente para diferenciar “zapatilla eléctrica” de calzado.
3. Puntuar cada candidato con rúbrica explícita: coincidencia sustentada, posible pista, irrelevante. Un puntaje de relevancia no prueba presencia física.
4. Si los candidatos iniciales son insuficientes, ampliar la búsqueda por bloques dentro del presupuesto. Para este inventario no se requiere una base vectorial externa.
5. Releer los resultados seleccionados y sus versiones antes de responder. Separar coincidencias activas de históricas/retiradas.
6. Mostrar código, descripción encontrada y ubicación registrada. Si solo aparece “varios de cocina”, decir que es una pista sin contenido detallado.

No descartar coincidencias exactas por un puntaje bajo. La recuperación debe medir recall: un buen reranker no puede recuperar una entrada que nunca recibió. Si se recorrió solo parte del inventario o hay registros desactualizados, no afirmar una ausencia definitiva. Usar “No encontré coincidencias” y ofrecer búsqueda ampliada/manual.

Las búsquedas normales de lista no llaman a IA por cada tecla. El usuario envía la búsqueda semántica explícitamente.

## Probabilidades y aclaraciones

Separar `score`, distribución de probabilidades y `confidence` específico del proveedor. Un resultado booleano de 0,98 es una estimación de verdad para la pregunta formulada, no una garantía universal de 98% de exactitud. No intercambiar estas métricas entre proveedores.

Seleccionar umbrales con datos etiquetados del dominio. No fijar 0,9 como verdad universal. Hasta completar la evaluación, las referencias con varios candidatos plausibles presentan opciones. Si se cambian modelo, versión o instrucciones de forma material, repetir la evaluación afectada.

Las decisiones de permiso, pertenencia a mudanza, versiones, conteos y validación de códigos son deterministas; no dependen de un score.

## Costos y límites

- No publicar como actual una tarifa obtenida de un resumen comunitario. Verificar precios de Gateway/modelos en T00 y guardar fuente, fecha y unidad de cobro en configuración/documentación de operación.
- Presupuesto propuesto: USD 5 por mudanza; aviso al 80%. Previews y evaluaciones tienen presupuesto separado y pequeño.
- Persistir consumo por propósito: clasificación, búsqueda, extracción. Medir porcentaje de mensajes que necesitan generación y costo total por operación exitosa.
- Reservar presupuesto atómicamente antes de cada solicitud, usando una cota conservadora de entrada, salida y reintentos. Liquidar con el uso real informado. Solicitudes concurrentes no pueden gastar todas el mismo saldo.
- Un timeout de proveedor puede haber consumido tokens: mantener una reserva conservadora hasta reconciliarlo. El límite local controla nuevas solicitudes; no prometer igualdad instantánea con una factura que llega de forma asíncrona.
- Limitar tamaño de mensaje (default 4.000 caracteres), estado/candidatos, máximo de preguntas y tiempo total. No enviar todo el historial ni todo el inventario en cada turno.
- Cachear decisiones de lectura por consulta normalizada, IDs/versiones de candidatos, modelo e instrucciones. Invalidar al cambiar cualquiera. Una respuesta mutadora siempre revalida los datos, aunque se reuse su interpretación.
- Una única solicitud en proceso por UUID de mensaje, con lease y recuperación. Dos reintentos del mismo mensaje no deben disparar dos cadenas de IA sin control.
- Al alcanzar el presupuesto o ante indisponibilidad, mantener lectura, formularios, códigos y operaciones manuales. Explicar la limitación con texto breve.

## Evaluación requerida

Construir en T00 un conjunto inicial de 40 o más ejemplos etiquetados, usando descripciones reales de las referencias como material de prueba histórico y casos nuevos con respuestas esperadas explícitas. Incluir español/inglés, typos, negaciones, correcciones, múltiples intenciones, cantidades, IDs ambiguos, cierre concurrente y búsquedas por sinónimos.

Comparar tres rutas: determinista cuando aplica, Jev y fallback generativo. Medir exactitud de intención/selección, errores de mutación, recall de búsqueda, tasa de aclaración, latencia, costo y proporción de generación. No aumentar el uso de Jev si eso empeora integridad o hace perder contenido.

Objetivos iniciales: cero mutaciones automáticas incorrectas en casos críticos, 95% de acierto en intenciones simples no ambiguas del conjunto y 90% de recall@5 en búsquedas respondibles del conjunto. Son metas de aceptación del proyecto, no métricas ya medidas del proveedor. Si no se alcanzan, mejorar candidatos/instrucciones o aclarar; no rebajar silenciosamente los criterios.

## Voz

El dictado de iOS produce texto en el mismo campo. Jev procesa ese texto. La disponibilidad offline del dictado depende del dispositivo, idioma y sistema; no prometerla. Si se incorpora grabación propia en P1, hace falta un servicio de transcripción aparte con presupuesto, límites y pruebas en PWA instalada.


## Configuración de la ampliación v1 · 14/10/2026

El organizador autorizó el chat con IA y confirmó saldo en Gateway. Se usa autenticación automática OIDC de Vercel con `createGateway`; no se solicita clave propia de OpenAI. Previews no activan modelos pagados por defecto. La activación de producción queda versionada conforme al pedido del organizador. Los antiguos `AI_ENABLED=false`/`GENERATION_ENABLED=false` de instalación no la bloquean. Para desactivar operativamente se usan `AI_DISABLED=true` (ambos modelos) o `GENERATION_DISABLED=true` (solo extracción), que prevalecen también sobre los flags de activación. Fuera de producción los flags ENABLED=true son opt-in para pruebas aisladas. Next.js incluye únicamente el destino no secreto `CASA_BUILD_ENV`; runtime usa ese destino cuando VERCEL_ENV no está disponible. No se incrustan credenciales en el bundle.

El usuario pidió reemplazar Gemini 2.5 y GPT 5.4 por modelos mejores. Extracción usa **Claude Sonnet 5.5** (`anthropic/claude-sonnet-5.5`) por defecto; **Claude Opus 5.5** (`anthropic/claude-opus-5.5`) queda como alternativa configurable, sin una segunda llamada automática. Tarifas de Gateway verificadas el 14/10/2026, USD por millón de tokens de texto: [Jev](https://vercel.com/ai-gateway/models/jev) 0.04 entrada / 0 salida; [Sonnet 5.5](https://vercel.com/ai-gateway/models/claude-sonnet-5.5) 2 / 10; [Opus 5.5](https://vercel.com/ai-gateway/models/claude-opus-5.5) 4 / 20, para los pedidos acotados de esta aplicación. La elección sigue la prioridad de calidad solicitada; no constituye una calibración ya realizada sobre el inventario familiar. Valores heredados GENERATION_MODEL de Gemini 2.5 o GPT 5.4 se reemplazan por Sonnet, ignorando sus antiguas tarifas. Overrides de modelos conocidos nunca reducen la tarifa verificada; modelos desconocidos requieren tarifas explícitas. Se mantiene USD 5 por mudanza, cota conservadora por bytes y hasta 4096 tokens de salida (incluido razonamiento low), timeout de 30 segundos sin reintentos automáticos; AI_REQUEST_RESERVE_USD solo puede aumentar la reserva.

Reglas y texto literal preceden a IA. Jev clasifica intención y referencias finitas; controles simples usan plantillas. Solo pedidos que requieren argumentos libres pasan una vez por extracción Zod con citas literales y referencias de catálogo. Todas las mutaciones producidas por IA se presentan para confirmación mientras no haya calibración live suficiente. Los recibos se renderizan sin otra llamada generativa.

Búsqueda semántica revisa bloques de ocho registros (hasta tres bloques por mensaje) con preguntas independientes de coincidencia/pista/ninguna. Incluye nombres de unidades y contenido; muestra el alcance y permite continuar. La caché incluye modelo, versión de instrucciones y versiones de las entidades. Coincidencias exactas se conservan y resultados semánticos se releen antes de responder. Descripciones que exceden el límite del bloque no se recortan: el alcance queda pendiente para búsqueda manual.

`npm run eval:ai` sigue verificando cuarenta reglas offline. `npm run eval:ai -- --live --max-usd=0.05` evalúa otros cuarenta ejemplos semánticos etiquetados y registra modelo, costo o reserva, exactitud y p95. Requiere Gateway autenticado del entorno de prueba; CI ordinario no factura llamadas. Una prueba del botón de conexión verifica acceso y esquema, y no sustituye calibración ni validación de iPhone/multiusuario.
